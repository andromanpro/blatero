# Формат транскрипта Blatero

Начиная с этапа развития распознавания говорящих, каждая новая запись создаёт
два парных файла:

- `transcript.jsonl` — первичный версионированный журнал событий;
- `transcript.md` — читаемое представление для панели, подсказок и отчёта.

У следующих сегментов имена получают одинаковый номер:
`transcript-2.jsonl` + `transcript-2.md`. Старые сессии только с Markdown
продолжают работать; приложение не переписывает их автоматически.

## Записи JSONL

Первая строка содержит описание записи: версию схемы, `recording_id`, номер
сегмента, время общего старта, STT-провайдера, имена WAV и заданные пользователем
подписи каналов.

Каждая следующая строка — отдельное событие `utterance`:

```json
{
  "schema_version": 1,
  "record_type": "utterance",
  "event_id": "…",
  "recording_id": "…",
  "sequence": 12,
  "start_ms": 18420,
  "end_ms": 20910,
  "source": "loopback",
  "speaker_role": "Собеседник",
  "speaker_id": "remote_mix",
  "speaker_name": "Анна",
  "text": "Повторный запрос должен вернуть прежний результат.",
  "confidence": 0.91,
  "provider": "yandex",
  "audio_file": "audio-guest.wav",
  "status": "final",
  "timing_source": "provider",
  "words": []
}
```

`source` описывает происхождение события: `microphone`, `loopback`, `synthetic`,
`manual` или `import`. Канонические `speaker_role` пока остаются совместимыми с
интерфейсом: `Я` и `Собеседник`. `speaker_id` предназначен для будущих анонимных
кластеров `SPEAKER_NN`, а `speaker_name` — для проверенного пользователем имени.

Эхо-фильтр не уничтожает диагностические данные. Отброшенный микрофонный дубль
остаётся только в JSONL со `status: suppressed`, причиной
`cross_channel_echo` и оценкой `echo_similarity`. В Markdown попадают только
события `final`.

Запись JSONL и Markdown защищена межпроцессной блокировкой. Сначала сохраняется
первичное событие, затем читаемая строка: при аварии журнал остаётся достаточным
для восстановления.

## Восстановление Markdown

```powershell
.\.venv\Scripts\python.exe transcript_events.py rebuild `
  sessions\<сессия>\transcript.jsonl
```

Команда атомарно пересобирает парный `transcript.md`. Можно передать второй
аргумент и сохранить результат в другой файл.

Историческую сессию можно импортировать без изменения исходного Markdown и WAV:

```powershell
.\.venv\Scripts\python.exe transcript_events.py migrate `
  sessions\<сессия>\transcript.md
```

Старое время означало момент получения готового текста, поэтому границы реплики
помечаются как `legacy_result_timestamp_estimate`. Номер исходной строки и старый
timestamp сохраняются в `legacy_line` и `legacy_timestamp`. Существующий JSONL
команда не перезаписывает.

## Полностью локальное перераспознавание и кластеры голосов

Для архивной записи можно получить новые временные метки сегментов и слов без
отправки аудио во внешние сервисы:

```powershell
.\.venv\Scripts\python.exe transcript_backfill.py sessions\<сессия> `
  --audio audio-me.wav --model small
```

Команда не заменяет первичный журнал и создаёт `transcript.local.jsonl`.
В смешанной записи KTalk файл `audio-me.wav` может содержать и микрофон, и звук
из наушников; поэтому техническая метка `mixed_capture` не означает, что всю
дорожку произнёс владелец микрофона.

Модели разделения говорящих устанавливаются один раз, локально:

```powershell
.\.venv\Scripts\python.exe speaker_diarization.py install-models
.\.venv\Scripts\python.exe speaker_diarization.py run sessions\<сессия> `
  --audio audio-me.wav --speakers 4
.\.venv\Scripts\python.exe speaker_diarization.py merge sessions\<сессия>
```

Загрузчик проверяет закреплённые SHA-256. Обработка выполняется на CPU через
`sherpa-onnx`; исходный WAV и текст не передаются наружу. Результаты:

- `diarization.json` — временные интервалы анонимных кластеров;
- `transcript.local.diarized.jsonl` — локальный текст, разделённый по границам
  слов при смене кластера;
- `evidence.diarized.html` — страница прослушивания, доступная в архиве по ссылке
  «кластеры голосов».

На странице можно дать кластеру имя, указать «мой голос» или «другой участник» и
объединить два ошибочно разделённых кластера. Для каждого голоса выводятся до
трёх коротких примеров. Кнопка **«с этой реплики — новый голос»** добавляет
ручную границу разделения; новые реплики получают виртуальный идентификатор
`SPEAKER_NN_SPLIT_NN`. Настройки атомарно сохраняются в
`speaker-map.json`, а `transcript.refined.jsonl` и `transcript.refined.md`
пересобираются без повторного запуска модели. Следующий итоговый отчёт использует
проверенный Markdown только после назначения имён всем необъединённым кластерам;
живые подсказки продолжают читать первичный транскрипт. Неполная карта хранится
как черновик и не меняет источник отчёта.

`SPEAKER_00` и аналогичные значения не являются именами или распознанными
личностями. Их нельзя автоматически переносить в оценку кандидата: сначала
нужно прослушать примеры и назначить имена вручную. Состав и лицензии моделей
описаны в [`DIARIZATION_MODELS.md`](DIARIZATION_MODELS.md).

## Импорт готовой расшифровки

Панель содержит адаптеры Microsoft Teams (VTT/DOCX), Zoom (VTT), Яндекс
Телемоста (TXT/DOCX/PDF) и Контур.Толка (TXT), а также универсальный импорт
SRT/VTT/JSON. Источник выбирается явно либо определяется по расширению и
содержимому. Импорт всегда создаёт новый сегмент и не перезаписывает существующие
журналы. Исходный загруженный файл не сохраняется; ограничения — 2 МБ,
200 страниц PDF и 10 000 реплик. DOCX читается без запуска Word и без распаковки
на диск, PDF — только как текст. Для JSON распознаются массивы и контейнеры
`utterances`, `segments`, `transcript`, `messages` и `items`; время можно
передать в секундах или миллисекундах. Текстовый формат может содержать таймкод
до или после имени, например:

```text
00:00 Алексей
Добрый день
00:07 Анна: Здравствуйте
```

Провайдер события включает адаптер и контейнер, например `import:teams-vtt`,
`import:zoom-vtt`, `import:telemost-docx` или `import:kontur-talk-txt`, а
исходная подпись участника — в `speaker_name`.

## Эталон и метрики

Черновик ручной разметки создаётся из первичного журнала:

```powershell
.\.venv\Scripts\python.exe transcript_eval.py init `
  sessions\<сессия>\transcript.jsonl `
  sessions\<сессия>\transcript.reference.jsonl
```

В копии нужно проверить `text`, `start_ms`, `end_ms`, `source`, `speaker_id` и
`status`. Для неправильно удалённой эхо-фильтром реплики `status` меняется с
`suppressed` на `final`. Повторяемые изменения можно хранить в отдельном
JSON-патче, где ключом служит `sequence`:

```powershell
.\.venv\Scripts\python.exe transcript_eval.py annotate `
  sessions\<сессия>\transcript.reference.jsonl `
  sessions\<сессия>\transcript.reference.patch.json
```

Команда принимает только поля разметки и не позволяет заменить `event_id` или
другие служебные идентификаторы. После ручной проверки:

```powershell
.\.venv\Scripts\python.exe transcript_eval.py finalize `
  sessions\<сессия>\transcript.reference.jsonl

.\.venv\Scripts\python.exe transcript_eval.py score-dir sessions
```

`score-dir` одной командой считает WER, DER, JER, ошибку/покрытие физического
канала, precision/recall эхо-фильтра и долю ложных подавлений для всех найденных
пар. Черновые эталоны намеренно не оцениваются: иначе копия результата могла бы
создать ложные идеальные метрики без ручной проверки.

Для локальной проверки текста и аудио строится автономная временная шкала:

```powershell
.\.venv\Scripts\python.exe evidence.py sessions\<сессия>
.\.venv\Scripts\python.exe evidence.py sessions\<сессия> --reference
.\.venv\Scripts\python.exe evidence.py sessions\<сессия> `
  --journal transcript.local.diarized.jsonl --output evidence.diarized.html
```

Вторая команда показывает черновую эталонную роль, анонимный идентификатор
спикера и канал. Кнопка у реплики запускает связанный WAV с приблизительного
начала. При генерации нового отчёта такая шкала создаётся автоматически, а
точные отметки вида `[13:20:11]` превращаются в ссылки на реплику и аудио.

## Приватность и удаление

JSONL содержит тот же распознанный разговор, что и Markdown, плюс точные времена
и технические метаданные. К нему применяются те же правила доступа и хранения.
Действие «очистить результат» удаляет оба формата и WAV, но сохраняет настройки
и подготовительные материалы встречи.
