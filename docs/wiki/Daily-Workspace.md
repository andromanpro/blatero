# Сегодня: ежедневный экран

Откройте «Сегодня» в общей шапке Blatero. Экран доступен и со страницы встречи,
и с доски: `/projects?view=daily`. Он работает локально, без модели и микрофона.

## Один фокус

Выберите задачу и нажмите «Сохранить фокус». В карточке есть та же команда —
«Сделать текущей задачей». Выбор хранится в базе между перезагрузками и окнами.
Он не меняет статус задачи. Фокус общий для пространства: при выборе другого
проекта текущая задача остаётся видна с названием своего проекта.

В фокусе показаны суть и следующий шаг. Метод и причина выбора раскрываются
отдельно; сначала можно нажать «Вспомнить метод» и пересказать своими словами.
После завершения задачи экран предложит выбрать новую, без автоматической замены.
«Новая задача» позволяет создать карточку прямо здесь.

## Решения для пользователя

В карточке раскройте «Запросить решение»: запишите конкретный вопрос и рекомендацию
с причиной. Агент может сделать то же через CLI или авторизованный API. У одной
задачи может быть один открытый вопрос; повтор того же запроса не создаёт дубль.

Ежедневный экран показывает до трёх вопросов. «Все вопросы» раскрывает остальные.
«Ответить в карточке» открывает вопрос, текущий контекст и поле «Моё решение».
Ответ сохраняется в истории карточки и доступен агенту через `context`.
Он не принимает поставку и не переписывает метод автоматически: агент отдельно
вносит согласованное решение в актуальные поля карточки.

Если суть, метод, причина или следующий шаг изменились после вопроса, экран
отмечает это. Устаревшая редакция не может сохранить ответ поверх новой.
Рабочий агент не может ответить вместо пользователя, выбрать за него фокус
или отметить темы для ежедневного закрепления.

«Результаты на проверке» — отдельный сворачиваемый список новых карточек в статусе
«На проверке». Восстановленные исторические статусы туда не подмешиваются.
Сама готовность к проверке не означает, что сформулирован вопрос пользователю.

## Ближайший план

Показаны до шести ближайших элементов за семь дней, считая сегодня по Москве:
встречи, интервалы задач, сроки и даты публикации статей Гранки. Завершившиеся
интервалы скрыты, текущие остаются. Пересечения отмечаются. «Открыть весь план»
ведёт в недельное расписание; начало и длительность задаются в карточке.

При выборе проекта показаны связанные с ним материалы и задачи. Личный внешний
календарь остаётся общим и отмечен отдельно. Он читается из последнего локального
снимка; экран не запускает синхронизацию, запись встречи или публикацию статьи.

## Короткое закрепление

В важной карточке нажмите «Закреплять важное решение». Для тренировки нужны
заполненные суть, метод и причина. Ежедневный экран предлагает максимум две темы,
сначала только с названием и поводом для возвращения.

1. Нажмите «Попробовать вспомнить».
2. Своими словами воспроизведите цель, метод и причину — текстом или вслух.
3. Нажмите «Показать карточку и сверить».
4. Оцените себя: не вспомнил — возвращение через день; частично — через три;
   помню — через семь.

После оценки тема уходит из сегодняшней очереди, следующая появляется на её месте.
Изменение сути, метода или причины возвращает тему в очередь сразу. Изменение
времени в плане или статуса не сбрасывает закрепление для новых самооценок.
У старых оценок без сохранённого отпечатка содержания используется редакция
карточки: любое её изменение может предложить повторное возвращение.

Это добровольная самооценка, а не оценка ИИ. Пересказ не сохраняется, уведомлений
и автоматической проверки понимания нет. Отметку закрепления можно снять в карточке.
Завершённые задачи тоже можно закреплять: приёмка результата не означает, что
решение уже запомнилось.

Закрытые как неактуальные карточки исключены из фокуса, очереди внимания,
плана задач и повторения. История вопросов и закрепления сохраняется. Вернуть
карточку можно вручную во вкладке «Закрытые»; после восстановления её сохранённые
план и отметка закрепления снова учитываются. Исходные встречи и публикации
остаются в календаре независимо от закрытия связанной задачи.

## Агентский интерфейс

```text
project_cli.py daily --project PROJECT_UUID
project_cli.py decision-request TASK_UUID --revision N --question "Что выбрать?" --recommendation "Вариант и причина"
project_cli.py context TASK_UUID
```

API: `GET /api/projects/agent/daily`, `GET /api/projects/agent/daily/task/UUID`,
`POST /api/projects/agent/daily/request` с `work_item_id`, `revision`, `question`,
`recommendation`. Агент передаёт Bearer-ключ. Эти команды обращаются к локальной
базе напрямую; запрос решения не проходит через файловую очередь повторной доставки.
При временной занятости агент должен повторить тот же запрос после перечитывания
контекста. Совпадающий открытый вопрос идемпотентен; другой вопрос не затирает его.

Запросы решения не извлекаются автоматически из всех прежних переписок. Сначала
агент формулирует действительно актуальный вопрос, затем пользователь отвечает.
Поиск по задачам и ограничение периода истории на ежедневном экране не применяются:
вопросы, план и закрепление ограничиваются выбранным проектом.

## Отвеченные вопросы и ответы из чата

На экране «Сегодня» и в карточке есть свёрнутая по умолчанию группа
«Отвеченные · N». В ней сохраняются вопрос, ответ и дата. Для ответа из чата
дополнительно доступны исходная цитата, идентификатор чата и расположение
первичного сообщения. В очереди внимания остаются только открытые вопросы.
Фильтр проекта применяется и к истории ответов.

Агент записывает фактически полученный ответ отдельной локальной командой:

```text
project_cli.py decision-answer --json-file answer.json
```

Поля JSON: `request_id` (новый UUID для новой записи), `work_item_id`, прочитанная
`revision` карточки, `id` вопроса, прочитанная `decision_revision`, точный
`question`, `answer` для этой карточки, полная исходная `quote`, `session_id`
и `reference_id` зарегистрированного в карточке `source_span`.

Первый адаптер поддерживает сообщения пользователя из подключённой истории
Codex (`.jsonl` и `.jsonl.zst`, для сжатых нужен Python 3.14). Источник должен
указывать строку сообщения; его SHA-256 считается по распакованным байтам
от начала журнала до этой строки включительно. Команда проверяет роль user,
полную цитату (в том числе answer в ответе на вопрос интерфейса), хеш, чат и
дату после постановки вопроса. Пересказ агента и произвольный файл не подходят.

Большой несжатый журнал читается порциями: размер истории сам по себе не
отменяет ответ. В памяти остаётся только выбранное сообщение, не больше 8 МиБ.
Есть ограничение времени чтения 120 секунд. Для сжатого журнала дополнительно
действует предел распаковки префикса 512 МиБ. Проверка SHA охватывает все исходные
байты до конца строки; создание отдельной вырезки вместо первичного журнала
не требуется и не заменяет проверку источника.

Запись получает состояние `answered` и пометку «Записан агентом из чата».
Нативный ответ пользователя в интерфейсе остаётся `resolved`. Оба состояния
попадают в «Отвеченные». При повторной доставке используется прежний request_id
и тот же JSON: повтор не повышает редакцию и не создаёт вторую запись.
Изменённый повтор, устаревшие редакции и уже отвеченный вопрос дают конфликт.

Регистрация ответа повышает редакцию карточки, но не меняет её статус, метод,
приёмку или подтверждение знаний. Маршрут owner-only daily/resolve не расширен
до worker. Чтение журналов выполняет CLI, не HTTP и не хук. Хук напоминает агенту
о записи ответа; он не угадывает решения по произвольному тексту переписки.
