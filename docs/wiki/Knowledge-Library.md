# Общая библиотека знаний

В общем меню выберите **Библиотека** (`/projects?view=knowledge`). Здесь собраны
паспорта проектов, досье задач, предложения решений, выбранные документы,
материалы встреч/Гранки и доступная история Codex, Claude Code, Hermes, OpenCode.

## Найти и вернуться к сути

1. Выберите проект слева. Без выбора поиск охватывает весь подключённый каталог.
2. Введите слова или начало слов, например `архитектур` или `остатки HTTP`.
3. Уточните тип: документ, решение, досье задачи, обсуждение.
4. Откройте найденный фрагмент. Проверьте путь, время индексации, состояние,
   основания и ограничение объёма. Из материала можно перейти к связанной задаче.
5. В карточке задачи ссылка «Открыть досье в библиотеке» показывает её материалы.

Поиск читает локальный индекс и не запускает извлечение документов или модель.
Текст показывается безопасно, без исполнения HTML и команд из источника.
Предыдущие версии открываются из истории материала. Архивная редакция не
означает актуальное решение; для продолжения вернитесь к текущей записи.

## Состояние и актуальность

| Метка | Что означает |
|---|---|
| Источник | Текст исходного материала; содержание не получило автоматическую приёмку |
| Предложение | Объяснение агента, ожидающее проверки пользователем |
| Подтверждено | Пользователь подтвердил содержание знания; это не завершает задачу |
| По последнему снимку | Индекс соответствует последней обработанной версии источника |
| Изменение в очереди | Обнаружено изменение, новый текст ещё обрабатывается |
| Нужна перепроверка | Основание знания изменилось или недоступно; прежнее подтверждение сохранено отдельно |
| Источник недоступен / Ошибка обновления | Файл отсутствует, превышен лимит или не удалось извлечь текст |

Свежесть файла не доказывает правильность документа. Старое предложение
сохраняет свой исторический смысл даже после реализации; актуальное объяснение
нужно записать отдельным знанием со ссылками на новые основания.

## Зафиксировать объяснение

В открытом источнике нажмите «Зафиксировать знание по этому источнику», запишите
суть и причину выбора. Сохраняется предложение с отпечатком прочитанного
основания. Интерфейс ставит операцию в долговечную очередь независимого worker
и ждёт результат. Изменившееся основание или конфликт редакций требует перечитать
материал. «Подтвердить содержание» доступно пользователю отдельно.

## Независимое обновление

Обработчик работает отдельным процессом, если он настроен в этой установке.
Автозапуск при входе в Windows включается отдельно. Открытое окно Blatero
для настроенного обработчика не требуется. Изменения документов объединяются,
журналы читаются с сохранённой позиции; периодическая сверка подхватывает
пропущенные события. Имеющиеся хуки Codex/Claude передают только указатель на
журнал в очередь, без разбора текста и вызова модели.

Путь служебного каталога показан в состоянии библиотеки. В нём отдельный
SQLite-индекс, конфигурация источников и очередь. Для установки с явно заданным
каталогом данных используется его `.knowledge`; путь может быть переопределён
при настройке. Это отдельная база от `.projects/projects.sqlite3`.
Каталог Markdown задаётся при настройке обработчика.
`generated` содержит снимки доски (править их через карточки); `notes` — знания
с основаниями; `history` — подтверждения. Удалённая публикация не настроена.
Папку можно открыть отдельно, в том числе в Obsidian.

Worker использует пониженный приоритет, один тяжёлый разбор одновременно,
порции до пяти операций и бюджет 1,5 с между ними; отдельный разбор документа
ограничен 12 с. При записи встречи, загрузке CPU от 85% или свободной памяти
меньше 768 МБ тяжёлая работа приостанавливается. Малые запросы сохранения знаний
обрабатываются и при ручной паузе. Кнопка «Приостановить» не закрывает поиск.

Панель показывает очередь, последнюю обработку и ошибки. После выключения
компьютера сбор возобновится при следующем входе. Круглосуточный NAS-сервис
не включён.

## Область подключения

Реестр зависит от выбранных проектов и локальных папок этой установки. Он может
включать документы проектов, паспорта доски, источники карточек, тексты встреч
и явно подключённые журналы агентов. Поставка не содержит индекс, переписки
или папки разработчика. Новый проект с отдельной папкой подхватывается следующей
сверкой. Общая родительская папка не определяет принадлежность; неоднозначные записи остаются
непривязанными. Смена задачи в сессии применяется по времени явной привязки.

Для документов выбираются корневые материалы и документальные подпапки,
а не весь диск или все исходники. Поддержаны MD/TXT/RST/DOCX/PDF, отдельный JSON-
реестр ADR. Материалы Гранки поступают через существующий каталог описаний;
это не обещание полного текста всех статей. HerdR и закрытые приложения без
доступной истории требуют отдельного адаптера или экспорта.

Лимиты: файл 10 МБ; извлечение 250 000 символов; PDF — 300 страниц; сообщение — 32 000
символов. Сокращение отмечается. OCR не включён. Обход одного дерева ограничен
300 каталогами, глубиной 6 и 3000 документами; достижение лимита отражается в
состоянии источников. Непрерывно растущие журналы обрабатываются порциями.
Первичное заполнение идёт в фоне и не означает, что весь архив уже прочитан.

Журналы Codex и Claude Code читаются также из `.jsonl.zst` (обработчик
Python 3.14). Сжатие и перенос в архив не создают новую сессию: сохраняются
идентификатор потока и позиция в распакованных байтах. При наличии обеих копий
выбирается обычный `.jsonl`. Ссылки на новые фрагменты указывают реальный архив
и номер строки; прежние ссылки остаются в истории.

Распаковка выполняется только фоновым обработчиком в удаляемый локальный кэш:
до 128 МиБ на архив, до 10 секунд на распаковку, суммарно до 256 МиБ готовых
файлов кэша. Прочитанный кэш удаляется; исходники не меняются. Повреждённые,
обрезанные и превышающие лимит архивы показываются как ошибки очереди,
а не как успешный сбор. Разовый каталогизатор истории также читает сжатые
журналы и считает SHA-256 по распакованным байтам.

## Настроить отдельную библиотеку

Это дополнительная возможность, не условие записи встреч. В новой portable-
установке фоновой индексации и автозапуска ещё может не быть. Сначала создайте
проекты и задайте их рабочие папки. Затем из корня распакованного пакета:

```powershell
.\runtime\python.exe .\app\knowledge_cli.py --home 'C:/BlateroData/.knowledge' init --board 'C:/BlateroData/.projects/projects.sqlite3' --notes 'C:/BlateroNotes' --without-history
.\runtime\python.exe .\app\knowledge_worker.py --home 'C:/BlateroData/.knowledge'
```

Замените примеры путей своими. `--home` должен совпадать с каталогом библиотеки,
который читает панель; задайте `BLATERO_KNOWLEDGE_HOME` перед запуском Blatero,
если выбрали отдельное место. Не инициализируйте существующую библиотеку повторно.
Проверьте созданный `config.json`: `project_roots`, `extra_files`, `history` и
`session_providers` определяют область чтения. `--without-history` отключает
журналы агентов; для их подключения настройте источники отдельно. Это локальное
чтение личной истории, не обязательная часть установки.

Для автозапуска выполните `knowledge_cli.py --home ПУТЬ install-startup` тем же
Python. Команда создаёт пользовательский VBS в папке автозагрузки и сообщает
его путь. Для отмены удалите именно этот ярлык при остановленном обработчике;
индекс и оригиналы останутся. Сжатые журналы требуют отдельного Python 3.14:
portable Python 3.12 не получает эту возможность от переключения языка.

## Для агента и локального API

```text
runtime\python.exe app\knowledge_cli.py status
runtime\python.exe app\knowledge_cli.py search архитектур --project PROJECT_UUID
runtime\python.exe app\knowledge_cli.py detail SOURCE_ID
runtime\python.exe app\knowledge_cli.py propose --json-file note.json
```

`note.json`: `title`, `body`, `kind`, `project_id`, `task_id`,
`references:[{id,content_hash}]`; для правки также `id` и прочитанная `revision`.
Агент создаёт draft. Содержательный вывод записывается после чтения оснований.

API использует прежнюю защиту панели и Bearer worker-ключ: GET `library`,
GET `library/status`, GET `library/item/ID`; POST `agent/library/notes` возвращает
`command_id` и состояние. Читайте GET `agent/library/commands/ID` до `complete`
или `failed`. Повторяйте тот же `command_id` с тем же содержанием для
идемпотентного повтора. После конфликта перечитайте источник/редакцию.
Подтверждение и управление паузой доступны пользователю. Хранилище и поиск
не зависят от конкретной модели; автоматический платный синтез не включён.
