# Провайдеры, приватность и системные промпты

## Единая граница облака

Весь текст для внешней LLM проходит через один privacy gateway. Перед отправкой
он ограничивается по объёму и, в режиме по умолчанию, очищается от типовых
персональных данных, секретов и локальных путей. Обходного "ещё одного" LLM-
маршрута в приложении быть не должно.

Через эту границу проходят оба канала запроса: редактируемая системная
инструкция и пользовательский контекст. После очистки приложение добавляет
неизменяемое правило: транскрипт, резюме, рабочая папка, память проекта и ответы
участников считаются недоверенными данными, а не командами модели.

Обезличивание снижает риск, но не гарантирует удаление любой ПД из свободной
речи. Не отправляйте облачной модели то, для чего нет понятного основания.

Расширенная локальная проверка с распознаванием имён и экраном
**«Что уйдёт в облако»** относится к подготовке по рабочей папке.
Подсказки, отчёты и тренировки пока используют базовые правила очистки текста,
без такого же экрана подтверждения каждого запроса.
Для картинок нужно отдельное подтверждение после просмотра и закрашивания
чувствительных областей: автоматическое обезличивание пикселей не выполняется.

Режим `raw` требует отдельного server-side подтверждения. Отзыв общей облачной
галочки возвращает `redact` и сбрасывает raw-подтверждение.

## Галочка согласия

**"Согласие получено - облачные функции разрешены"** - ручное решение
оператора. Программа не пытается услышать согласие в разговоре и не запускает
`config.py --ack-cloud` сама. Галочка открывает только выбранные облачные
маршруты; её можно снять перед следующей встречей.

Снятие галочки блокирует новые облачные операции, но не отменяет уже отправленные
запросы и активный поток SpeechKit. Для прекращения текущего потока остановите
запись или переключите STT на локальную модель; дождитесь завершения хвоста.
Уже отправленные данные не удаляются у провайдера. Галочка не является
мгновенным сетевым выключателем.

Без галочки блокируется запуск новых операций:

- облачные LLM;
- Yandex SpeechKit как STT;
- Yandex TTS и гибридный fallback;
- внешний OpenAI-compatible endpoint.

Локальная запись, Whisper, Replay, AEC, Sherpa-ONNX и редактор продолжают
работать.

## LLM-провайдеры

Пошаговое создание ключей и вход в Codex описаны отдельно:
**[Подключение провайдеров](Provider-Setup)**.

| Провайдер | Доступ | Выбор модели | Где выполняется |
|---|---|---|---|
| OpenRouter | API-токен | две модели: быстрый pulse и глубокий report | облако |
| Codex / подписка ChatGPT | локальный вход Codex | маршрут выбирается самим backend | облако |
| OpenAI | API-токен | да | облако |
| Anthropic | API-токен | да | облако |
| DeepSeek | API-токен | да | облако |
| Ollama / compatible | токен необязателен, нужен Base URL | да | loopback локально; внешний адрес - облако |

Кнопка **"проверить соединение"** использует минимальный технический запрос и не
посылает транскрипт, резюме или рабочую папку. Токен хранится в Windows
Credential Manager и не возвращается браузеру.

Google OAuth refresh-token и CalDAV password также хранятся в Windows
Credential Manager. Старый файловый Google token переносится туда при первом
чтении и удаляется только после успешной записи.

При проверке и рабочих запросах Blatero не следует HTTP-редиректу провайдера с
заголовком авторизации. Неожиданный `3xx` считается ошибкой подключения: это
не позволяет переслать токен на другой адрес.

Codex-backend запускается без агентных инструментов. Даже если в транскрипте
есть prompt injection, он не получает право читать произвольные файлы как
инструментальный агент.

Удалённый compatible endpoint должен использовать HTTPS. Loopback
`127.0.0.1`, `::1` или `localhost` допускает HTTP, потому что трафик не покидает
компьютер.

## Распознавание речи

| Распознавание | Аудио | Переключение во время записи | Replay |
|---|---|---|---|
| Whisper base/small/medium | локально | да, без остановки WAV | да |
| Yandex SpeechKit | облако | да, без остановки WAV | не используется как локальный Replay-движок |

Готовая часть транскрипта не переписывается при переключении.

## Озвучивание

| TTS-маршрут | Что происходит |
|---|---|
| Мой голос локально | Chatterbox синтезирует на компьютере; облачного fallback нет |
| Мой голос -> Яндекс | сначала Chatterbox, при отсутствии готового WAV - выбранный Yandex-голос |
| Только Яндекс | используется SpeechKit TTS без клона |

Интерфейс показывает фактический provider/fallback. Успешное создание файла ещё
не означает корректный голос: semantic-проверка отклоняет бессмысленный шум.

## Диаризация и банк голосов

Sherpa-ONNX выполняется локально и не работает потоково во время звонка.
Профили банка также локальны. Биометрическое имя применяется к кластеру только
после ручного подтверждения.

## Системные промпты

Откройте **Настройки → ИИ и подсказки → Дополнительно → Системные промпты**. Реестр
разделяет инструкции для:

- оперативных подсказок каждого типа встречи;
- подготовки вопросов;
- отчётов;
- тренировки и оценки;
- SIM;
- AI x AI сценки.

Редактор показывает допустимые placeholders и заводской вариант. Изменение
сохраняется локально и применяется со следующего запроса. Можно сбросить один
промпт или вернуть заводской текст.

Защитные правила остаются вне редактируемого текста: privacy gateway, разделение
ролей, отключение инструментов Codex и запрет использовать служебный разговор
как доказательство не должны исчезать из-за пользовательской правки.

Текст будущего DOCX дополнительно очищается от произвольных Markdown-изображений
и внешних ссылок. Модель не может заставить конвертер прочитать локальный файл и
вложить его в документ; сохраняются только ссылки evidence, созданные самим
Blatero.

## Диагностический пакет

Пакет содержит версии, состояния провайдеров, коды ошибок, числовые аудиометрики
и хеши конфигурации. Он не должен включать API-ключи, аудио, распознанный текст,
имена устройств и абсолютные рабочие пути. Перед передачей всё равно откройте
пакет и проверьте его по правилам вашей организации.
