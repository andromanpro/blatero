# End-to-end processes

Use this as an action checklist. The [settings reference](Settings-Reference.md)
explains fields; [troubleshooting](Troubleshooting.md) explains failures.

## 1. First real meeting

1. Extract/start portable and read the [recording/pilot rules](Recording-and-Policy.md).
2. Configure audio and an optional AI route, then save.
3. New meeting → topic, or project/tasks/time → load/review context → create.
4. Run Check all: click readiness, speak after the countdown, then stay quiet.
5. Record → audio or audio+video; for video choose/preview the exact source.
6. Confirm your recording basis; use hints/scenario during the conversation.
7. Stop → Finish and create report. Check unknown voices if necessary.
8. Review conclusions, create DOCX, confirm selected agreements for memory.

Result: separate source audio, canonical transcript, diagnostics and reviewed
report. Task acceptance remains a separate user action.

## 2. A repeat project meeting

Create a **new** meeting for the same project rather than overwriting the old
session. Select current tasks, include completed/history only if relevant, load
registries/documents and confirm choices. Previous reports are sources, not
confirmed agreements. Confirmed project memory is reused. Inspect date/time,
topic and missing context, then create/open. No AI or recording starts merely
because preparation is local. [Preparation](Meetings-and-Preparation.md).

## 3. A test without mixing work

Select the test environment in meeting parameters, create/open a test session,
then record/import/Replay. Use synthetic material rather than sensitive work.
Cleanup is optional and destructive: calculate/review the categories first.
Resetting results keeps meeting metadata/scenario/materials, not generated audio.

## 4. Prepare from local files or diagrams

Set/check the workspace, read the material inventory, then prepare context.
Review recipient/text/files and custom hidden terms. For images, select/mask/
recheck and separately acknowledge pixels. Close cancels sending. Confirm only
the intended packet; changed source/route invalidates it. Empty/unreadable input
does not trigger a fabricated dossier. [Formats and limits](Meetings-and-Preparation.md).

## 5. A file arrives during the meeting

Use + material to upload/drop/paste a copy. Review before analysis; the RAW audio
continues. A screenshot uploads only the selected crop. Folder watching notices
changes but never sends automatically. Read new findings and rebuild a saved
report explicitly if needed. [Live materials](Live-Materials.md).

## 6. Import or re-recognize an existing meeting

In Maintenance → Audio and speakers choose import for a supported transcript
adapter, or Replay for a saved WAV. Import adds a segment; Replay writes a separate
run. Check complete transcript/history and source identity. Do not rename/delete
originals to force a preferred file. [Audio](Audio-and-Speakers.md).

## 7. Unknown or mixed voices

Quick participant review finds local clusters and proposed bank names. Listen,
name and save; voiceprint storage needs separate permission. For mixed clusters,
use detailed Replay/speaker review, split/merge and apply names to transcript
separately. The quick review alone does not rewrite a finished report.

## 8. Practice, repeat and compare

Settings → Practice → choose I answer / I ask / Both AI, or Speech. Prepare,
start explicitly, save an attempt, then request review. In speech practice choose
one change, record a separate repeat and compare source quotes. Ready reviews/
audio replay from disk; generating missing material is a separate potentially
paid operation. [Training](Training.md).

## 9. Save agreements and link work

After report, Review agreements → check basis → select/edit → project/client →
confirm. Unselected proposals remain drafts. Meeting tasks/Materials create or
link cards explicitly. A saved report/memory item does not automatically complete
or accept a card. Create the next related meeting from current tasks/memory.

## 10. Plan and recall

Set task start/duration, inspect weekly overlaps and local/calendar snapshots.
Choose an owner focus on Today. Mark important decisions for optional recall;
explain before revealing and self-rate for a 1/3/7-day return. No model grading,
recorded retelling or automatic reminder is implied. [Today](Daily-Workspace.md).

## 11. Export, delete or recover

Export a selected session into encrypted transfer and verify it before deleting
anything. Choose explicit data categories, calculate file list/size, confirm exact
target. A whole-session purge does not erase external copies or independent
exports. After a crash, repair first creates a byte-identical backup and fixes
only a provable incomplete tail; otherwise leave unchanged for manual inspection.

## 12. Update and roll back

In Maintenance stage a signed verified source-update ZIP, stop all capture/jobs,
then restart to apply. Inspect the available prior version before staging rollback.
Changed pinned dependencies require the complete compatible portable/installer,
not pip into the running environment. Keep data separate from code; package
integrity is not public Windows publisher trust. [Installation](Installation-Recovery-Updates.md).
